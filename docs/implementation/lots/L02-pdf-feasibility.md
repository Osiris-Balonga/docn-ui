## Stories and commits in order

### L02-S01 — `feat(pdf): render exact-size documents with local fonts`

- [x] Add a pinned engine and one minimal licensed static font; resolve assets separately for Node/browser.
- [x] Generate a two-page 85×55 mm card, accented text, and a small multipage table; inspect dimensions/content with an independent PDF reader.
- [x] Qualify trim/bleed/boxes; isolate post-processing and justify its dependency if needed.
- [x] Activate test:pdf with one reusable qualification suite, not one suite per size.

**Acceptance:** Dimensions within 0.1 pt, two correct sides, extracted French text, no third-party font request. Advertised boxes exist and are exact.

**Targeted verification:** pnpm test:pdf feasibility; inspect generated PDFs and their boxes.

### L02-S02 — `feat(pdf): isolate browser rendering and display generated bytes`

- [x] Create a versioned protocol with revision, serializable requests, and results; actual worker in the exported Next build.
- [x] Load PDF.js and its local worker; display a copy of the bytes and download the retained original.
- [x] Test a request change, an error, and destruction; one active task, no worker loop.
- [x] Keep the qualification page outside public navigation; transform/remove it after reuse in L05.

**Acceptance:** Static production, not only the development server, generates and displays an actual PDF without sustained UI blocking.

**Targeted verification:** Targeted protocol integration and one real browser smoke check with a build; do not duplicate geometry tests.

### L02-S03 — `test(pdf): qualify roll height pagination and print constraints`

- [x] Extend existing fixtures with short and long receipts at 58/80 mm; measure final height and verify the last text.
- [x] Trigger a height limit and document the error strategy; no approximate character-count calculation.
- [x] Render the pagination fixture and print profile; visually inspect a contact sheet of results.
- [x] Record the feasibility decision, tested versions, indicative timings, and limitations in QA/ADRs. Adapt the engine or post-processing now if required.

**Acceptance:** Every G1 risk has evidence or an explicit blocking decision; assume no unverified capability.

**Targeted verification:** pnpm test:pdf feasibility; qualified build/worker at the same SHA. No tests of all theme combinations.

## Exit criteria

G1 satisfied: dimensions, fonts, front/back, height, pagination, and worker proven. On failure, resolve it or propose an ADR before L04.

Update [status](../status.json) and create `docs/qa/L02.md` from the [template](../templates/QA_REPORT.md). Record actual commits, completed checks, and deviations. No additional suite without a distinct risk to cover.

## Out of scope

No public catalog, backend fallback, generic multiformat engine, or duplication of already sufficient fixtures.
