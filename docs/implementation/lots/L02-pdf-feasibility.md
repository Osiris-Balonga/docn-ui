## Stories et commits dans l'ordre

### L02-S01 — `feat(pdf): render exact-size documents with local fonts`

- [ ] Ajouter moteur épinglé et une police statique licenciée minimale ; résoudre assets séparément côté Node/browser.
- [ ] Générer une carte 85×55 mm à deux pages, un texte accentué et une petite table multipage ; un lecteur PDF indépendant inspecte dimensions et contenu.
- [ ] Qualifier coupe/fond perdu/boîtes ; si nécessaire isoler le post-traitement et justifier sa dépendance.
- [ ] Activer test:pdf avec une seule suite de qualification réutilisable, pas une suite par taille.

**Acceptation :** Dimensions à 0,1 pt, deux faces correctes, texte FR extrait, absence de requête de police tierce. Les boîtes annoncées sont présentes et exactes.

**Vérification ciblée :** pnpm test:pdf feasibility ; inspection des PDF générés et de leurs boîtes.

### L02-S02 — `feat(pdf): isolate browser rendering and display generated bytes`

- [ ] Créer protocole versionné avec revision, requête sérialisable et résultats ; worker réel dans le build Next exporté.
- [ ] Charger PDF.js et son worker local ; afficher une copie des octets et télécharger l'original conservé.
- [ ] Tester un changement de requête, une erreur et la destruction ; une seule tâche active, pas de boucle de workers.
- [ ] Garder la page de qualification hors navigation publique ; la transformer/retirer après réutilisation dans L05.

**Acceptation :** La production statique, pas seulement le dev server, produit et affiche un vrai PDF sans bloquer durablement l'UI.

**Vérification ciblée :** Integration du protocole ciblée, un smoke browser réel avec build ; ne pas dupliquer les tests de géométrie.

### L02-S03 — `test(pdf): qualify roll height pagination and print constraints`

- [ ] Ajouter aux fixtures existantes un reçu court et un long à largeur 58/80 mm ; mesurer la hauteur finale et vérifier le dernier texte.
- [ ] Provoquer une limite de hauteur et documenter la stratégie d'erreur ; aucun calcul approximatif par caractères.
- [ ] Rendre la fixture de pagination et le profil print ; examiner visuellement une planche contact des résultats.
- [ ] Écrire la décision de faisabilité, versions testées, timings indicatifs et limites dans QA/ADR. Adapter le moteur ou post-traitement maintenant si requis.

**Acceptation :** Chaque risque G1 a une preuve ou une décision bloquante explicitée ; aucune capacité non vérifiée n'est présumée disponible.

**Vérification ciblée :** pnpm test:pdf feasibility ; build/worker qualifié du même SHA. Pas de tests de toutes les combinaisons de thèmes.
