## Justification for added tests

S01 adds one unit file because the unit scope previously had no document-core suite. Its five cases cover distinct pre-render risks together: applying orientation once, rejecting template/format incompatibility with field paths, enforcing custom versus preset dimensions, preserving invalid data while reporting limits, and fingerprinting normalized requests. S02 adds one theme/asset file because token validation and path/hash controls are separate from format behavior. Its two cases group the three themes and four assets instead of creating a theme × weight × runtime matrix. S03 adds one measurement file with three separate low-level risks rather than component tests per primitive. S04 reuses the existing three-case queue integration file for the final protocol. Neither duplicates L02's real-PDF geometry assertions; the existing feasibility file contains the one real primitives composition.

## Visual and document checks

No PDF was generated for S01 because contracts and format resolution are pure functions, while L02 already proves the mm-to-point geometry with actual files. S02 extended that existing fixture with an editorial render using local Noto Serif headings and Noto Sans body text. PDF.js extracted French accents from both 85×55 mm pages. Poppler reported two 240.945×155.906 pt pages and a 9,751-byte PDF; both pages were rasterized at 144 DPI and inspected. The first render exposed a title/accent overlap on the back; using the bounded heading token there removed it, and the latest rasterization showed legible text, intact accents, consistent margins, and no overlap or clipping.

S03 rendered one 7,924-byte, one-page primitives card at the same exact size. PDF.js glyph positions were converted to top-left bounds and every measured text item stayed within the 3 mm safe frame. Its 144 DPI rasterization showed the Serif heading, bilingual supporting text, separator, and two field pairs with no clipping or overlap. PNG intermediates were removed and no visual snapshot matrix was added. Physical printing remains outside this lot.

## Deviations and resumption

Zod 4.5.2 was initially considered from the live npm metadata, but it had been published on the same day and caused pnpm to propose an age-policy exception. The exception was removed and the already locked MIT-licensed Zod 3.25.76 was promoted to a direct dependency instead, avoiding a second copy and preserving the existing supply-chain policy. The Noto Serif package tarball also stalled; exact versioned files were obtained from one package CDN and matched against a second mirror, with hashes recorded in the manifest. No runtime CDN request exists.

`pnpm test:pdf primitives` was tried once and correctly failed because the native positional filter matches file paths, while the primitives case intentionally remains in `feasibility.pdf.test.ts`. The targeted rerun used `pnpm test:pdf feasibility -t "composes shared primitives"`, then the complete `pnpm test:pdf feasibility` file passed with six cases.

S04 isolates feasibility fixtures from the reusable Node/browser adapters and moves the PDF viewer/worker protocol into `features/pdf-viewer` and `workers/pdf`. The worker now validates the shared `RenderRequest`, returns a serialized `RenderResult`, and fingerprints normalized inputs. `pdfjs-dist` remains confined to feasibility inspection rather than the reusable Node adapter. The loopback server was stopped after browser verification. Resume by pushing the verified branch and opening the L04 PR; no merge is authorized.
