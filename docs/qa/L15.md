## Scope

L15 prepares reproducible CI, static delivery and release governance without selecting or configuring a host. The build artifact now fingerprints both source inputs and every exported byte. E2E consumes that artifact, PDF CI also runs the approved visual references, and distribution filters include every shared input identified by the audit. A promotion-only policy requires the live `dev` SHA and an explicit `release-approved` label.

The local preview build uses `http://127.0.0.1:4173` for canonical and registry URLs, remains nonindexable, and applies portable security/cache rules. No production origin, license, author, hosting account, deployment, tag or package publication exists.

## Justification for added tests

The release-policy case protects the only route to `main` from a stale `dev` SHA or an unapproved promotion. The static-policy case prevents a host configuration from caching mutable registry/HTML indefinitely or omitting the worker boundary in CSP. Existing PDF, visual, consumer and browser suites were not duplicated locally; the current L14 evidence remains valid and CI will exercise the changed graph on the L15 PR.

## Static output and limitations

The verifier fetched the real exported files over HTTP rather than inspecting paths alone. Current previews use generated PNG pages; the unused `PdfCanvas` module is unreachable from the static catalog and therefore no standalone PDF.js worker is emitted. The runtime JavaScript and fonts that are actually shipped were verified. A future reachable worker must be added to the probe.

No provider-specific header file can be verified before a host is selected. No TLS, custom domain, CDN, public registry installation, deployment restoration, production rollback or indexing claim is made. The local artifact can be stopped, restarted and reverified; there is no previous production artifact to restore.
