# QA — L01 — Reproducible bootstrap and quality scopes

Date: 2026-08-29. Status: **in progress**. Branch `chore/bootstrap-workspace`; base `07dd743db42c293ed59f99e6ff734eaef94ea86b`. Issue [#3](https://github.com/Osiris-Balonga/docn-ui/issues/3).

## Scope

Two private workspaces, static Next.js export, shadcn Base UI, separate lightweight test scopes, and focused CI. No PDF generation, catalog, hosting, or new license decision.

## Environment and decisions

Windows / PowerShell; Node 24.18.0. The host's pnpm 11.19.0 is older than the project pin, so commands use `npm exec --yes --package=pnpm@11.24.0 -- pnpm <command>` without changing the global toolchain. This is the same pinned pnpm used by the package scripts and CI.

The initial direct `pnpm install` correctly rejected the mismatched engine before installing. Version resolution and dependency licenses are recorded in [DEPENDENCIES](../DEPENDENCIES.md). No application tests exist at the start of S01; installation, compiler, static build, and browser inspection provide its evidence.

## Results

### S01 — workspace

- `pnpm install --frozen-lockfile`: passed with pnpm 11.24.0; no lockfile changes.
- `pnpm typecheck`: passed for both workspaces, including generated static route types.
- `pnpm build`: passed with Next 16.3.3 / Turbopack; `/` and `/_not-found` prerendered, `out/index.html` and `out/404.html` produced.
- `pnpm preview`: served only the export at loopback port 4173 (checked unoccupied before startup). HTTP `/` = 200, `/not-a-route/` = 404 with custom recovery content.
- Actual browser DOM inspection confirmed the heading, honest unavailable-template status, and the correct repository link. No application suite added for scaffolding.
- Network download retries occurred during initial installation; the completed frozen-lockfile pass succeeded. The http-server transitive `whatwg-encoding@2.0.0` is deprecated; it is a development-server dependency, not browser code.
