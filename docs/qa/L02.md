## L02-S02 — static browser worker and exact-byte preview

The exported `/qualification/pdf/` route is intentionally absent from public navigation and carries `noindex`. Protocol version 1 accepts serializable card requests with monotonically increasing revisions. `LatestRenderQueue` allows one active render and replaces pending work with the latest request. The render worker uses React-pdf's browser `toBlob` path, then the same isolated box post-processor. The main thread retains the transferred result, passes a copied `ArrayBuffer` to PDF.js, and builds the download Blob from the retained original.

Verification:

- `pnpm test:integration` — one file, three cases passed: revision replacement, structured active-revision worker error with continuation, and idempotent destruction.
- `pnpm build` — passed with static routes `/`, `/_not-found`, and `/qualification/pdf`; the output contains the local Noto Sans WOFF, bundled render-worker chunk, and local `pdf.worker.min` module.
- Built site served from `apps/www/out` on loopback. A real browser rendered revision 1 as a two-page 6,832-byte PDF, displayed page one on canvas, exposed a Blob download, changed the name and rendered revision 2, then displayed page two.
- Visual inspection found and corrected a React-pdf fixed-page interaction: `wrap={false}` shrank the page layout tree while retaining the requested MediaBox. Default page wrapping plus a non-wrapping, absolutely positioned card content root preserves the full background and fixed geometry.

Next's Turbopack production build treated the TypeScript worker URL as a copied source asset rather than a bundled worker. The qualified production command therefore selects Next's supported webpack build explicitly; webpack emits executable worker JavaScript in the static output. No server fallback or remote asset was used.

## L02-S03 — measured roll height and gate decision

Receipt height uses two actual renders. The probe uses the configured maximum page height. PDF.js reads the real glyph baselines, glyph heights, final marker, and page count; the final render uses that measured extent plus a fixed 12 pt allowance for the renderer's pagination threshold. There is no character-count or line-height estimate. A probe spanning multiple pages, a missing marker, more than 300 lines, or a result beyond the configured physical limit fails with `RECEIPT_HEIGHT_LIMIT` or `RECEIPT_MEASUREMENT_FAILED`; content is never silently clipped.

`pnpm test:pdf` passed one five-case file in 2.35 s. The two added cases cover the four nominal receipt outputs together and the distinct height-limit failure. Poppler independently reported:
