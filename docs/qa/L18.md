## L18-S01 scope

The Node `renderPdf` facade validates the flat L17 input, validates an exact
runtime-options object, verifies the complete local font manifest by real-path
containment, size, and SHA-256, prepares bounded local images, constructs the
source-owned plan, dispatches fixed/flow plans through the existing finalizer,
and returns the released six-field `RenderResult`. Continuous plans now route a
facade-only measurement coordinator; the stable V1 Node adapter remains
byte-identical.

The input normalizer now uses private prepare/complete phases. The public
`normalizeTemplateInput` behavior remains synchronous and unchanged, while the
runtime continuation performs image preflight after the one permitted schema
parse. The continuation lives in a non-exported internal module and is absent
from both the root barrel and public `./template-contract` subpath. Theme-input presence is
captured in prepared immutable state before any runtime await, so caller
mutation cannot change the legacy-style decision. Implementation commit
`d6cef29b184784eda0b31aea6c2d7e49049f1e48` and corrective commits through
`b0559d1af564988a306e37081f446bd81c8ee251` are recorded in status; the
current corrective commit carrying this review evidence is intentionally not
self-recorded.

## L18-S02 scope

The `./browser` entry now exports the same flat `renderPdf` signature while
retaining the advanced fixed-document exports. Browser runtime options are an
exact plain-object boundary. The font base defaults to
`globalThis.location.origin`; explicit bases must remain on the same HTTP(S)
origin and cannot contain credentials. Each manifest font is fetched with
redirects disabled, rejects a mismatched declared length, is streamed under the
exact manifest byte bound, verified by SHA-256, snapshotted as a data URI, and
temporarily prioritized under a facade mutex. Existing advanced font ordering
is restored in `finally`; stale trusted load state from `Font.reset()` is
rearmed in place without source growth.

Validated local-image IDs are resolved only through the runtime resolver. The
shared bounded preflight owns its byte copies; the browser scope creates
runtime-owned Blob URLs, rolls back partial construction, and revokes every URL
once on success or failure. Result bytes are copied before return and remain
usable for independent caller preview/download copies after resource cleanup.
The direct S02 call has no cancellation, supersession, timeout, navigation, or
worker-termination event. L18-S04 owns those cleanup hooks with protocol V2;
S02 does not claim them prematurely.

## L18-S03 scope

The matching facades now dispatch the same bounded continuous feasibility plan.
The browser path parses the probe with a real package-local PDF.js worker rather
than importing a worker bundle on the caller thread or falling back to a fake
worker. Every loading task, `PDFWorker`, and underlying `Worker` is destroyed in
`finally`. The local worker entry relies on PDF.js's single dedicated-worker
bootstrap and does not register a second handler. A fixed `error` or
`messageerror` signal races document, page, and text loading; it removes both
listeners and terminates every worker resource without waiting on a stalled
loading-task disposal. The Node and browser facade-only measurers return the raw extent of
the complete final glyph bounds; the stable shared coordinator adds ADR 0003's
single 12 pt allowance. Stable V1 runtime, Node, browser, and
feasibility-adapter sources remain unchanged.

Continuous plans require an opaque `^[A-Z][A-Z0-9_]{0,31}$` final-marker token,
their exact continuous format, and the screen profile. The source-owned plan
renders the token as final standalone non-wrapping text, and the facade rejects
invalid tokens before document rendering. After the probe and final render, the
facade reopens the final PDF and requires exactly one page, the qualified width
and bounded height, and a true terminal marker that is an exact item or coherent
same-line PDF.js item sequence with a strict leading boundary, is the last and
lowest relevant text, and has every transformed glyph quadrilateral inside the
MediaBox. Probe and final qualification share this exact terminal-sequence rule.
The released `RenderResult` path then
reports the actual final page count and per-page point/mm dimensions for fixed,
flow, and continuous plans. Unexpected plan construction, renderer,
measurement, print-box, or result-inspection failures cross the facade as a
fixed `RENDER_FAILED` issue at `document`; existing `DocumentValidationError`
codes and paths are preserved. No raw exception text, marker, or document data
enters that fallback issue.

## Image and dependency evidence

`@pdf-lib/upng@1.0.1` (MIT) and `jpeg-js@0.4.4` (BSD-3-Clause) are exact direct
dependencies. The preflight checks source size and MIME signatures before full
pixel decode, validates every PNG chunk CRC, caps inflate at the exact declared
raster budget, limits JPEG decoder resolution and memory, rejects animated PNG,
and applies bounded EXIF orientations 1–8. PNG and rotated JPEG pixels are
deterministically re-encoded as metadata-free PNG. An unrotated JPEG is fully
decoded for validation, then retains its compressed scan while APP metadata and
comments are stripped; this prevents valid compact photos from expanding past
the byte limit. The normalized byte size, final pixel dimensions, MIME, and
SHA-256 form the descriptor. Resolver bytes and Node render-scope bytes are
copied independently; disposal is idempotent.

Node font preparation resolves and verifies each contained path once, then
converts the verified bytes to an immutable WOFF data source. The facade-owned
React PDF registration therefore consumes a digest-bound snapshot. Under the
pinned engine's process-global first-match store, the facade ensures a trusted
canonical source exists for every manifest slot, promotes it only for the
awaited render, and restores prior ordering in `finally`. The tests cover both
API call orders, a cached mismatched source, post-render advanced behavior, and
`Font.reset()`. Source counts remain stable across initial/repeated facade
renders, three reset/render cycles, and an advanced-first canonical data URI
that had already populated the shared registration cache. Facade renders are
serialized; concurrent mixed advanced/facade rendering and destructive
`Font.clear()` are outside the supported process-local contract.

The published npm unpacked sizes are 707,597 bytes and 76,029 bytes
respectively. The isolated codec entry measured 90,065 bytes minified / 31,617
bytes gzip, split as 70,328 / 23,724 for UPNG plus its `(MIT AND Zlib)` pako
1.0.11 dependency and 20,241 / 8,478 for jpeg-js. No stable budget is inferred.

Registry source closure remains unchanged by explicit scope decision and will

The current S03 `write: false` fixture measured the lazy continuous chunk at

## Limitations

S01-S03 do not expose the facade from the package root, change protocol V1,
migrate additional catalog templates, or add worker messages. The PDF.js worker
is internal measurement infrastructure, not protocol V2. Direct-call cleanup
covers success and failure;
interruptible worker cleanup remains S04. Existing advanced Node/browser render
functions and plan types remain available. The package entry is qualified
through the repository's TypeScript-aware test loader; raw Node TypeScript
stripping is not supported because extensionless source imports are unchanged.
