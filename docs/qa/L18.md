## L18-S01 scope

The Node `renderPdf` facade validates the flat L17 input, validates an exact
runtime-options object, verifies the complete local font manifest by real-path
containment, size, and SHA-256, prepares bounded local images, constructs the
source-owned plan, dispatches fixed/flow plans through the existing finalizer,
and returns the released six-field `RenderResult`. Continuous plans route the
existing qualified Node measurement path, but complete cross-runtime
continuous qualification remains L18-S03.

The input normalizer now uses private prepare/complete phases. The public
`normalizeTemplateInput` behavior remains synchronous and unchanged, while the
runtime continuation performs image preflight after the one permitted schema
parse. The continuation lives in a non-exported internal module and is absent
from both the root barrel and public `./template-contract` subpath. Theme-input presence is
captured in prepared immutable state before any runtime await, so caller
mutation cannot change the legacy-style decision. Implementation commit
`d6cef29b184784eda0b31aea6c2d7e49049f1e48` and first corrective commit
`a13a6912ee6c3e3ee3967d02aea9e7bbef481307` are recorded in status; the
current corrective commit carrying this review evidence is intentionally not
self-recorded.

## Image and dependency evidence

`@pdf-lib/upng@1.0.1` (MIT) and `jpeg-js@0.4.4` (BSD-3-Clause) are exact direct
dependencies. The preflight checks source size and MIME signatures before full
pixel decode, validates every PNG chunk CRC, caps inflate at the exact declared
raster budget, limits JPEG decoder resolution and memory, rejects animated PNG,
and applies bounded EXIF orientations 1–8. PNG and rotated JPEG pixels are
deterministically re-encoded as metadata-free PNG. An unrotated JPEG is fully
decoded for validation, then retains its compressed scan while APP metadata and
comments are stripped; this prevents valid compact photos from expanding past
the byte limit. The normalized byte size, final pixel dimensions, MIME, and
SHA-256 form the descriptor. Resolver bytes and Node render-scope bytes are
copied independently; disposal is idempotent.

Node font preparation resolves and verifies each contained path once, then
converts the verified bytes to an immutable WOFF data source. The downstream
React PDF font loader therefore consumes the digest-bound snapshot rather than
reopening a path that could change after verification. The facade also inspects
React PDF's process-global font store immediately before synchronous
registration and rejects any earlier conflicting source for the same qualified
family, weight, and style.

The published npm unpacked sizes are 707,597 bytes and 76,029 bytes
respectively. The isolated codec entry measured 90,065 bytes minified / 31,617
bytes gzip, split as 70,328 / 23,724 for UPNG plus its `(MIT AND Zlib)` pako
1.0.11 dependency and 20,241 / 8,478 for jpeg-js. No stable budget is inferred.
The site does not import the new Node facade; application-level browser impact
remains L18-S02 work. Registry source closure remains unchanged in S01 by
explicit scope decision and will be created for the new public workflow in L22.

## Limitations

S01 does not expose the facade from the package root, change the browser entry,
change protocol V1, migrate additional catalog templates, add worker messages,
or claim complete continuous result/error parity. The existing advanced Node
render functions and plan types remain available. The package entry is qualified
through the repository's TypeScript-aware test loader; raw Node TypeScript
stripping is not supported because extensionless source imports are unchanged.
