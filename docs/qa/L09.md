## Justification for added tests

Money uses a new unit file because tax rounding and safe-integer overflow are pure economic rules reused by receipts and invoices. The existing PDF family pattern was extended with one receipt file covering nominal compositions, the distinct long-roll risk, and recovery from a physical limit. No format × theme × locale matrix was added. The existing feasibility suite was consolidated instead of duplicating height logic. Existing consumer and catalog journeys changed only where the shared registry closure and new family changed observable behavior.

## Visual and document checks

Retained local PDFs were rasterized with Poppler and inspected at 120–144 DPI. Retail is 58 mm wide and renders a clear merchant hierarchy, wrapped item label, taxes, strong total, payment, and final marker. Hospitality and Service are 80 mm wide with visibly distinct table/service and customer/provider structures. All use a white monochrome-safe surface and readable 7.5–8 pt body text; no theme introduces a large dark thermal background. The committed Retail catalog PNG is the selected receipt visual reference, while all three catalog previews form the manual contact check.

The long 58 mm fixture is one continuous page, exceeds A4 height as intended, remains below 2,000 mm, and contains its 80th line, total, and footer. Automated checks prove digital dimensions and content, not physical printer calibration.

## Deviations and resumption

The lot specification mentioned an editor/form connection. Explicit maintainer direction removed customization/export forms from template pages, so L09 connects receipts to the accepted catalog, install-copy action, primary-source drawer, render plans, and registry without restoring that rejected UI.

The first consumer rerun exposed two distribution consequences: `money.ts` increased each shared card closure from 29 to 30 files, and the measured Node runtime required its already-pinned `pdfjs-dist` dependency to be declared in the registry. Commit `f698b2e` corrects both and the full external scenario then passed. Earlier attempts using host pnpm 11.19.0 did not execute tests because the repository correctly rejected the wrong version; final evidence used a temporary Corepack shim for exactly 11.24.0, then removed its files.

Paper-roll width is not guaranteed printable width. The thermal guide requires 100% / actual-size printing, disables fit-to-page, explains hardware margins and the 2,000 mm recovery, and does not claim ESC/POS support or universal printer compatibility. No physical printer was available, so paper sensitivity, heat, speed, cutter offsets, driver margins, and actual printed scale remain unverified. PR #29 is open; the next permissible step is to observe exact-head CI and request explicit merge authorization.
