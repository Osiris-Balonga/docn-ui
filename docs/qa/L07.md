## Justification for added tests

S01 added one three-case unit file because graph closure and source rewriting are pure security/distribution boundaries that the existing PDF and UI suites cannot cover. S02 adds one two-case file for the distinct binary-download boundary and reuses the existing theme/resolver case after changing resolver configuration. S03 adds one two-case component file for source closure/copy behavior; the real-browser check reuses one existing template route rather than adding another E2E file. Remaining planned coverage is limited to two distinct isolated consumers. Static verification covers every item; the expensive real CLI path will install one business-card dependency graph rather than all three cards.

## Visual and document checks

S02 qualifies retrieval and local placement of the exact font/license bytes, but it still does not claim that an external consumer can render. Generated files are deterministic build artifacts ignored under `apps/www/public/r/`, and the static export contains the same development registry and assets. Consumer rendering in S04 will reuse the existing card geometry/content assertions and inspect one actual installed PDF; it will not create a second template matrix.
