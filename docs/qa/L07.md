## Justification for added tests

S01 added one three-case unit file because graph closure and source rewriting are pure security/distribution boundaries that the existing PDF and UI suites cannot cover. S02 adds one two-case file for the distinct binary-download boundary and reuses the existing theme/resolver case after changing resolver configuration. S03 adds one two-case component file for source closure/copy behavior; the real-browser check reuses one existing template route rather than adding another E2E file. S04 adds one orchestral consumer case, not one test per environment or template. It shares one minimal-card request across two external projects and checks the CLI, dependency closure, assets, builds, offline render, network boundary, PDF dimensions, and essential text. Static verification still covers every item; the expensive path does not reinstall the editorial and studio cards that share the same graph. The review correction adds one case to the existing playground component file because tab replacement is the only new interaction boundary; it relies on the existing catalog and playground E2E journeys for the rest.
