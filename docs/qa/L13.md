## Scope

L13 hardens the current static catalog rather than resurrecting the removed public editor. Family tabs now implement arrow/Home/End keyboard behavior, mobile users retain a named PDF download action, and page/zoom changes have one polite screen-reader announcement. The optional PDF.js canvas releases its page, loading task and backing bitmap, lazy-loads the engine, and rejects documents above the shared 50-page limit. Final rewritten PDFs enforce the same page limit and the existing 20 MiB limit.

PNG/JPEG data URLs now require matching binary signatures in addition to allowed MIME, encoding and byte limits. Existing remote-source and unsafe-link rejection remains unchanged. The local static server applies an explicit CSP and defensive response headers. Weekly Dependabot PRs cover npm and GitHub Actions without automatic merging.

## Justification for added tests

The existing content contract case was extended for the missing MIME/signature risk. One focused unit file was added because the final-PDF page boundary is post-processing behavior, not input-schema or visual geometry behavior. The existing catalog E2E was extended instead of adding accessibility, security and responsive suites per combination. No timing threshold was placed in tests because workstation timing is not deterministic CI behavior.

## Visual, accessibility, and privacy boundaries

The current preview reader presents source-owned preview images with text alternatives and keyboard controls; it does not expose a PDF.js text layer. Selectable PDF text does not establish tagging, reading order or PDF/UA conformance. Consumers requiring accessible documents must provide an HTML or structured-data alternative and separately qualify generated files.

Only actual Chromium was exercised in this lot. Firefox, Safari and iOS Safari were unavailable and are not claimed. Physical printing, screen-reader software, PDF/UA, PDF/X, CMYK and hardware barcode scanning remain unverified. Private document data is absent from the static catalog journey; browser/Node consumer generation remains local as previously qualified. The CSP permits inline script/style only where required by the actual Next static export and retains `object-src 'none'`, same-origin defaults and explicit local blob worker/image allowances.

## Deviations and resumption

The L13 specification referenced an active editor queue, edit transitions and form/export error states inherited from historical lots. Those surfaces were deliberately removed from the current V1 catalog before L13. This lot therefore hardened the surviving preview canvas and documented caller-owned scheduling rather than adding an unused coordinator. The 15-second value is a recommended consumer recovery budget, not an enforced library cancellation primitive; `@react-pdf/renderer` work already started by a consumer cannot be cancelled by docn-ui.

The local `pnpm` executable was 11.19.0 while the repository requires 11.24.0. Recorded checks used the exact Corepack version explicitly; no global tool or lockfile was changed. The next permissible step is remote PR validation and authorized merge. L14 must perform the broader qualification matrix, including any available non-Chromium and physical-print checks, without converting absence into a compatibility claim.

The React review correctly identified that effect cleanup must retain the canvas node captured when the effect starts. Commit `9f54f36` fixed the lint warning but a semicolon-separated verification command continued to commit after TypeScript rejected the nested function's lost narrowing. Per the no-history-rewrite rule, `35e6a3a` immediately changed the function to a narrowed closure; application TypeScript and focused lint then passed. The intermediate commit was neither pushed nor presented as verified, and the deviation is retained here instead of amended away.
