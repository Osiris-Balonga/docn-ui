## Justification for added tests

The invoice schema extends the existing unit scope because due-date ordering, duplicate identifiers, and explicit row-height limits are invoice-specific validation risks not covered by money tests. The existing invoice PDF file carries both the family nominal table and the single representative multipage risk; it does not cross formats, themes, locales, and line counts. One E2E file was required by the lot to prove the new family's direct route, previews, and source surface, but it does not duplicate monetary or pagination assertions from PDF tests. The existing consumer orchestration now splits the two qualified environments across distinct dependency closures instead of adding another external project or reinstalling all variants.

## Visual and document checks

Minimal uses a light open table and compact contact hierarchy. Business uses formal seller/customer blocks and a dark structured header. Studio uses an accent-led identity field and a stronger project/total hierarchy. The committed catalog images are generated from the nominal PDFs and their final SHA-256 values are recorded in the catalog manifest.

The representative Business fixture renders 72 lines across four A4 pages. A long accessibility-review label wraps inside one row; no row overlaps the next. Every page repeats identity, parties, column labels, invoice number, and page count. The last page contains line 72, subtotal `7,200.00 USD`, tax `1,440.00 USD`, total `8,640.00 USD`, notes, terms, and legal fields. This is digital layout evidence, not a physical printer or jurisdictional invoice qualification.

## Deviations and resumption

The lot specification originally requested a public line-item form and an E2E line-addition/download journey. The maintainer explicitly removed customization and export forms from template pages and approved the shadcn Charts-style preview/copy/source surface. L11 therefore does not restore that rejected UI. Typed render plans, strict invoice data, actual PDF tests, and external source installation qualify the underlying capability; the E2E journey qualifies the approved public surface.

V1 tax uses integer minor-unit prices, integer quantities, basis-point rates, and per-line half-up rounding. It is deterministic but not jurisdictional tax, bookkeeping, credit-note, or certified electronic-invoicing software. No physical printer was available; actual scale, hardware margins, duplex behavior, and color output remain unverified. L11 is locally verified and in review.
