## Justification for added tests

S01 adds date/payload and print-geometry coverage at unit scope, plus one actual-PDF raster/decode case because existing tests verified only QR matrix construction and visual presence, not independent decoding from final PDF bytes. The density case covers docn-ui's physical sizing boundary rather than retesting the third-party encoder. Later stories will extend the same ticket-family PDF file rather than creating one suite per composition.

## Visual and document checks

The S01 qualification page was rendered at 144 DPI and inspected: its 112 pt vector QR is square, undistorted, surrounded by the required four-module light quiet zone, and separated from readable event metadata. Automated raster decoding passed. Classic is the selected visual reference, with its exact PNG hash recorded in the catalog manifest. The contact sheet confirms that Classic uses a broad event field and detachable-style stub, Conference uses a portrait attendee hierarchy, and Live uses a saturated performance field plus isolated access panel. This proves digital generation and raster readability for fixed fixtures, not a printed scan.

## Deviations and resumption

The maintained `qrcode` dependency and vector primitive already existed from L05. S01 strengthens that shared primitive instead of adding a competing encoder or runtime dependency. Two exact test-only dependencies were declared: `@napi-rs/canvas` was already locked through PDF.js and supplies the Node raster canvas, while `jsQR` independently decodes pixels; neither enters runtime browser bundles. Next 16.3.3 generated scoped `apps/www/AGENTS.md` and `CLAUDE.md` during the running development server, so they were retained in a separate traceable commit as their generated instruction requires.

The lot specification mentioned a family customization form, but explicit maintainer direction removed customization/export forms from the public template experience. S02 therefore adds no hidden or unused ticket form: the public catalog exposes previews, install-copy, and primary source exactly like the accepted Charts-style layout. Generation remains qualified through the document plans and PDF suite. Similarly, the earlier export E2E no longer exists because the maintainer explicitly removed the Download PDF action from this page; S03 extends the existing catalog/source journey instead of restoring that rejected UI.

The first PR CI consumer run failed because the existing exact installed-source count still expected 28 files per consumer after `qr-code.ts` became an explicit registry primitive source. Commit `f285b2abd1dede008c14549adb2d6361354209f7` updates the expected closure to 29 files per consumer and explicitly requires the QR source in both installations. The full isolated consumer case then passed locally; this is a test expectation correction, not a reduction of the installed closure.

The final exact-head rerun passed all seven required checks at `8ec27ec86e0b8e0d6f13ed13b486349853d9fbd9`. The maintainer then explicitly authorized merging and proceeding. PR #28 merged through the protected branch as merge commit `4cb0ebf9e3b57037790201b14bfea0cd1386a700`; L08 is merged, not released.
